# Handover to the Mac: NightHack, 2026-10-30

For whoever runs Frank on the Mac tonight. Everything below is on `origin/dev`. It was built and tested on the Windows PC this afternoon, with no head, no keys and no camera. **Nothing in it has run on the real head yet**, so do the checks in step 3 before the doors open.

## 1. What's new since this morning

- **The face engine** (`frank/engine/`, [FACE_ENGINE.md](FACE_ENGINE.md)) moves Frank's eyes, lids and brows, plus the emotion part of the mouth, 50 times a second. Claude's expression tags say what he feels; the engine decides how and when it shows. Blinks, glances and looking away while thinking are automatic, and the eyes follow whoever is talking. It starts by itself with `frank` (`--no-face` turns it off and brings back the old `gaze.py` eyes).
- **The 3D body twin** (`perform/`): Cogley's CAD head on screen, moving exactly as the real head is told to. It needs the **body server**, which now owns the mouth board's USB port. Frank and the slider windows talk to the head through it at `socket://127.0.0.1:8811`.
- **The emotion map**: drag a point over pleasant ↔ unpleasant and calm ↔ aroused, and his face (on screen and on the head) becomes that feeling. **Release** gives the face back to Claude.
- **Frank's page is new**: one retro green-terminal page with tabs. The **live face editor** has every value the engine uses, moving as the conversation goes.
- Also in: Anushhka's evening commits (Frank explains how he works, knows he's at NightHack, talks 1.5× faster), the enclosure v1 work (decisions renumbered D30 and D31), a statechart editor and an online demo (both off by default, section 7).

## 2. Get it onto the Mac

```
cd <the repo>
git pull                  # needs Git LFS: the twin's 3D model (output/twin/frank.glb) comes through it
git lfs pull              # only if output/twin/frank.glb is a small text file after the pull
```

`frank/.env` (the keys) and `frank/voice.json` stay as they are on the Mac.

## 3. Before the doors open (about 15 minutes)

1. **Power:** the BOARD POWER jumper on both boards, both XT60s on 5 V, the link wires as in [firmware/README.md](../firmware/README.md). Plug the mouth board's USB into the Mac. Keep the servo bus at 5.0–5.1 V or more while things move.
   - **Servo extremes, once, before anything else.** The eye board's program has no per-servo limits, and jumps straight to any angle from −27 to 207. So in the slider window, drive every eye, lid and brow servo to the engine's extremes: eyes ±30° left-right and ±15° up-down, brows +35° and −20°, each lid at its saved SHUT and OPEN. A servo that hums without stopping is stalled at about 0.7 A: press ALL LOOSE and pull its range in. CUL's lid servo was replaced, so recheck that lid's poses.
   - **The jaw:** `cogley_mouth_main.py` never lets the jaw go, so `mouth_closed` must only just touch, or both MG996Rs strain all night.
   - Poses saved under one board program don't carry over to the other. They map degrees to pulses differently, up to about 9° apart near the ends.
   - Touch every servo after 10 minutes of running. A hot one is straining.
2. **Start the body server** (terminal 1; keep it open all night):
   ```
   uv run --no-project --with pyserial python perform/body.py robots/frank/robot.json --port /dev/cu.usbmodem2101
   ```
   Use the board's real port: `ls /dev/cu.usbmodem*`. Without the head, `--sim` in place of `--port ...` runs the twin on its own. **Start it first: it alone opens the board.** Frank, the engine and the slider windows all get `socket://127.0.0.1:8811`, never the `/dev/...` port. The twin page (http://127.0.0.1:8810) stays on "Loading" if `git lfs pull` was skipped.
   - **Twin calibration:** the eyes' left-right and up-down directions and the mouth zeros (assumed 90) aren't checked against the head yet. At http://127.0.0.1:8810, click a part, set its zero or flip its direction until the twin matches the real head, then **Save**, which writes `robots/frank/robot.json`. The twin shows what the head was *told*, not a measurement. A part drawn red ("can't reach") means a servo pushing against its own linkage: back that angle off.
3. **Check the face on the head, before Claude is involved** (terminal 2):
   ```
   uv run --no-project --with pyserial --with numpy python frank/engine/preview.py --head socket://127.0.0.1:8811
   ```
   Open http://127.0.0.1:8820 and use the emotion map and the tag buttons:
   - **curious**: both brows rise. **skeptical**: Frank's *own left* brow (on your right as you face him) goes up.
   - **surprised**: both upper lids open wide. Press **blink** (or B): both lids shut and open.
   - Drag the visitor dot to the right of the pad (his left): his eyes follow it.
   - The 3D twin next to it does the same.

   **If something is the wrong way round:** edit [frank/engine/rig.json](../frank/engine/rig.json).
   - A brow end that goes down instead of up: flip its `dir`.
   - The wrong brow rises: set `swap_brow_sides`.
   - The wrong eye narrows: set `swap_lid_sides`.
   - The eyes go the wrong way: change the sign of `gaze_x_sign` or `UD_UP`.
   - A dead or buzzing servo: put its socket name in `disabled`.

   Save, then restart `preview.py`. If a lid buzzes at either end, re-save that lid's SHUT and OPEN poses in the slider window (`firmware/servo_controls.py socket://127.0.0.1:8811 --link`). Run the slider window before Frank starts, never during the show, because it resets the board. Stop `preview.py` when the head looks right (Ctrl+C): Frank serves the same editor himself.
4. **Watch the jaw once:** if the closed mouth presses the lips together, the jaw servos strain all night. Back `mouth_closed` off a little in `mouth_controls.py`.

## 4. Run the show

Terminal 1: the body server (step 3.2), still running. Terminal 2:

```
frank --mouth socket://127.0.0.1:8811
```

(`frank` is the alias for `frank/start.sh`: web.py with the microphone on, Sonnet and the MacBook speakers.)

| Page | What it is |
|---|---|
| http://127.0.0.1:8800 | Frank's page: tabs **P** People, **F** Face (the 3D head, the engine's readouts, the emotion map), **E** Engine. Keys: **M** mic, **V** voice, **S** settings, **C** colour, **1–0** tags on the Face tab, **Esc** closes. |
| http://127.0.0.1:8820 | The live face editor: the same engine as the conversation, with every value and the decisions feed |
| http://127.0.0.1:8810/?hero=1 | The 3D twin alone, full screen (`&spin=0` stops the slow sway): good on a second screen facing visitors |

**Frank off the laptop** (added 20:20 on the Mac): https://frank-live.vercel.app/?key=<password> shows this same page, live, to anyone with the link. Behind it: terminal 3 `uv run --no-project --with aiohttp python frank/public.py --key <password>` (the password door, 8801, in front of 8800 and the twin on 8810) and terminal 4 `cloudflared tunnel --url http://127.0.0.1:8801`. When cloudflared restarts it prints a new address: `frank/live/point.sh https://<new>.trycloudflare.com` points the Vercel name at it. Details in [frank/README.md](../frank/README.md) (`public.py`).

**First live run of the new page:** it has only been run with a pretend conversation. Check typing, **M** (mic) and **V** (voice), Settings (brain, speaker, Test, Mouth check, eyes) and the camera feed. The single-letter keys work whenever no text box has focus, so **click into the message box before typing**, or letters will switch things. **C** (colour) shows the twin's red "can't reach" parts.

**Prompt to animation:** in the Face tab (and the editor), write what Frank should do and press **Animate** (Ctrl+Enter). Claude writes a short performance and it plays on the head and the twin; **Replay** and **Stop** are beside it. It uses the Mac's key in `frank/.env`.

**Steering him by hand:** drag on the emotion map. Use the dominance slider to choose between skeptical or irritated (up) and vulnerable (down). **Release** hands the face back to Claude. While you steer, Claude's expressions wait.

## 5. If something goes wrong

| What you see | Do this |
|---|---|
| A page says "refused to connect" | The program behind it isn't running: 8800 and 8820 are `frank`, 8810 is the body server. Start it, or read its terminal for the error. |
| `frank` can't open the mouth | The body server isn't running (start it first), or another program holds the board's port. Only the body server may open it. |
| The twin says NO SIGNAL | Start the body server, then reload the page. |
| The face does nothing on the head, but the twin moves | The board side: power, the BOARD POWER jumper, the link wires, or the board reset (the Pico dropped off USB). Restart the body server. |
| The eyes twitch between two programs | Something else is driving the eyes (an old slider window, `gaze.py`). Close it. With the engine on, nothing else should send to the eye board. |
| The face engine misbehaves | `frank --mouth socket://127.0.0.1:8811 --no-face`: the old behaviour (jaw from the voice, `gaze.py` eyes). |
| Frank goes silent mid-show | Read terminal 2. The "Hmm." filler crash is fixed; the voice now has a watchdog (Anushhka). |
| Everything's stuck | Ctrl+C both terminals, start the body server, then `frank` again. |

## 7. Built tonight but switched off

- **Statechart editor** (`frank/statechart/`, port 8830): Frank's conversation states as an editable chart. Not used by `frank`. To switch it on:
  1. In `frank/chat.py`'s `start_face()`, replace `from engine import Engine` / `Engine(writer=...` with `from statechart.bridge import ChartedEngine` / `ChartedEngine(writer=...`, with the same arguments.
  2. Run `frank/statechart/tests/test_bridge.py` first.

  It reads `frank/statechart/charts/frank.json` and picks up saved edits within a second; a chart with errors is ignored.
- **Frank online** (`frank/online/`): a public browser demo of the face engine at https://frank-face.vercel.app. A watcher on the Windows PC (`watch.py`) rebuilds and deploys it from *that PC's* files, so Mac edits reach the site only once pulled there. There is no need to deploy from the Mac tonight. If you must:
  1. `npm i -g vercel` and `vercel login`.
  2. `vercel link --yes --project frank-face --scope larzlarsenator-9296s-projects --cwd output/online`.
  3. **Straight away**, `vercel git disconnect --yes --cwd output/online`: linking connects the repository by itself, and the next push would publish Cogley's private files.
  4. `python3 frank/online/build.py && vercel deploy output/online --prod --yes`.

  Never deploy the repository root, and never put keys into Vercel: the page is public.
